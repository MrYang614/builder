# Editable examples

Open `two-storeys.building` in the application. It contains two editable levels, eight thick walls, two windows, two doors with opposite hinge/opening settings, independent wall A/B images, floor/ceiling materials, and an explicit roof slab. The second door is saved half open. Each wall side has a declared closure seam; its physical tile width remains 0.5 m.

`two-storeys-open-roof.building` is the same document with the roof removed. Loading and exporting it must leave the top open. Its IDs match the roofed example. The adjacent `.source.json` files are readable formal data for inspection; `.building` is the portable application file, with all image resources bundled by content hash.

The corresponding `.glb` files were generated by the application's shared geometry/material/door pipeline in Chromium, then independently reloaded and checked with Khronos glTF Validator. Detailed results are in `docs/export-validation.json`. This browser evidence does not claim desktop Windows or macOS acceptance.

Each GLB contains these individually playable clips:

- `Door_example_door_level_1_Open`
- `Door_example_door_level_1_Close`
- `Door_example_door_level_2_Open`
- `Door_example_door_level_2_Close`

Select a clip in a standard glTF viewer and play it from the start. Each acts on its own hinge only; the frame stays fixed. The saved static half-open pose is independent of the full clip endpoints.

The brick, plaster, wood and tile images are original procedural patterns generated for this repository. They use no external photographs or third-party image assets and are available for redistribution and embedding with this project under CC0-1.0. The original PNG files are in `apps/desktop/src/assets`.

Reproduce the files and their validation records with `npx playwright test tests/export-samples.spec.ts` after installing the project's Chromium dependency. The test uses the actual browser exporter, project-container encoder/decoder and an independent glTF load; it keeps sample IDs deterministic.
