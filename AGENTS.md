# Building Editor

Read docs/PRD-v0.3.md and docs/PROGRESS.md before continuing. Preserve unrelated files.

Required architecture: Tauri 2 / React / TypeScript / native Three.js / Rust. Single window, WebView, primary Canvas. No iframe, R3F, Next.js, backend service or plugin architecture.
EditorCore alone owns immutable formal project data. UI and pointer edits use the same commands. Preview never changes document; one drag creates one history item. Separate project, session, runtime and local settings. Core/geometry have no React, DOM, Tauri or UI dependencies. UI package has no building/Three/Tauri dependencies. Imports use public exports. Change sets update affected geometry and continuity; renderer survives UI changes. Dispose events, scheduling and GPU resources. Export independent revision snapshot through shared builders, without display overlays. No per-frame global React or IPC.

UI colors only from @building/ui semantic tokens, raw values only in packages/ui/src/tokens/source.json; generated CSS checked. Model material data in core presets is a registered exception. shadcn components live in packages/ui. Add both themes for any new key. Run npm run check, npm test, npm run build and relevant E2E/Rust tests.

Code conventions: read docs/CODE-QUALITY.md. Use the pinned local oxfmt and oxlint via npm run format and npm run lint:fix; npm run check enforces formatting, zero-warning lint and architecture/token rules. Keep explicit brace blocks and type imports. No blanket lint/type suppression. Preserve documented snapshot and instrumentation exceptions. Never format pinned Skills, generated token CSS or original PRD/acceptance conditions; their ignore patterns are intentional. npm run typecheck also checks node configuration and pure core/geometry targets.

Maintenance rules: keep hand-written TypeScript and Rust source files at or below 500 lines. Generated files, lockfiles, vendored code, and test files whose length comes from scenario matrices or instrumentation are outside this cap; keep tests focused and split reusable helpers when that improves clarity. Existing oversized production files have per-file line ceilings in `scripts/check.mjs`; each ceiling is the current reviewed baseline and must never rise. Reduce a ceiling when refactoring brings a file below it, then remove its exception once it is at or below 500 lines. Do not add an exception without recording the file's responsibility boundary and why splitting it would harm cohesion. Public business functions, lifecycle methods, asynchronous transitions, and resource owners need a concise comment that states purpose and any important state, side-effect, or performance constraint. `npm run check` enforces file-size ceilings; reviewers enforce comment usefulness because a text or AST check cannot reliably assess whether a comment explains real intent. Keep render mode, post-processing history, and path-tracing ownership in the runtime; UI controls issue runtime commands and never own GPU resources.

Before UI design read .agents/skills/frontend-design/SKILL.md. During React work read .agents/skills/vercel-composition-patterns/SKILL.md. After runnable UI use .agents/skills/impeccable/SKILL.md audit/critique/harden/polish and record issues. These files are project-installed, pinned, readable skills; no automatic hook trust is implied.

Q2 user approved designated closure seam while preserving physical texture size. T-branch routing still requires explicit evidence. Q5 target systems/hardware pending. Acceptance statuses: 未实现 / 已实现未验证 / 验证通过 / 验证失败 / 环境阻塞 / 需求待确认. Never label browser tests desktop or macOS acceptance. Maintain docs/ACCEPTANCE.md with requirement, implementation, test, evidence and limitation.

UI copy and layout verification: keep new or changed Chinese and English labels, help text, and dropdown options concise and clear; preserve meaningful units and editing consequences. Size inputs and dropdowns for their role and content rather than applying one width to every control; selected dropdown values must remain fully readable. Natural text wrapping is acceptable when it does not disrupt adjacent controls or layout. Keep changes local to the affected UI.

Editor decimal inputs and point-coordinate readouts show at most two fractional digits. Reuse the editor Numeric adapter with precision=2; normalize explicit numeric edits, while focus, display formatting, and exact snapping must not silently round existing formal project data.

Verify new or changed inputs, text, and dropdowns with actual Chinese and English screenshots. Check relevant themes at the default window size and minimum 900×600, including narrow panels when affected; inspect selected values, wrapping, clipping, and neighboring controls. Keep screenshots, traces, logs, benchmarks and generated reports in ignored .test-artifacts/; do not commit them or create a new dated test/review document for each change. Maintain concise current status and limitations in PROGRESS.md, ACCEPTANCE.md and KNOWN-ISSUES.md without claiming browser evidence as native acceptance. Match additional tests to the change; copy-only edits do not require an unrelated full regression suite. Reuse the editor, WebGPU or Storybook Playwright configuration; select individual tests or --grep instead of adding a task-specific configuration.
