# Editor design

Mode: Operate. Main artifact is the editable building viewport. Layout: compact two-row toolbar, 190px floor list, flexible single Canvas, 280px contextual inspector, bottom status. Controls left aligned with units beside numeric labels, one action per button. No decorative motion. Segoe UI Variable and native Chinese fonts remain offline; operating-system familiarity and readable numeric fields take priority over display typography.

Palette source: packages/ui/src/tokens/source.json. Blue ink, paper surfaces, restrained cyan selection; both themes expose identical semantic keys. Building colors and lighting do not derive from theme. Per the 2026-10-04 user request, header and modeling toolbar actions show SVG icons with localized hover/focus tooltips and accessible names; active tool keeps its pressed state and the status bar gives the editing hint. New, Open, Save, Save as, Undo, and Redo form the left header group. A theme icon button directly toggles light and dark; language and the actual renderer retain icon selectors on the right, followed by native minimize/maximize-or-restore/close controls in desktop mode. Project name and unsaved state remain readable metadata; the native title bar is removed and noninteractive header areas move the window. Empty state gives direct creation steps. Error text names affected validation and retains current data/input. Inspector composes wall/slab/opening fields and face material panels; no generic boolean-heavy mega-component.

The header project name is centered across the full window without an app title. It is plain display text with no tooltip, focus target, or pointer change. Saved or unsaved status follows Undo and Redo in the left group, with its existing copy, colors, and document behavior. In desktop mode, pressing any header area outside interactive controls starts native window dragging; double-clicking that area maximizes or restores the window. Buttons, disabled button wrappers, selectors, and their portal menus retain their own input behavior.

The latest user request replaces the original three-mode appearance requirement with only light and dark. The current-mode Sun or Moon icon has an accessible Appearance toggle name, dark pressed state, and localized hover/focus description. There is no theme popup or operating-system theme listener. Explicit light/dark preferences survive restart; legacy system, missing, and invalid values resolve to fixed light while preserving valid language and renderer preferences. The desktop window starts at 1600×900, with the existing 900×600 minimum.
